## 3. 主实验的训练设置

采用 `google-bert/bert-base-uncased`，全参数微调为 60 类单标签分类器；模型与 tokenizer 都固定同一个 Hugging Face commit。该模型的英语定位与 en-US 任务相符，参见 [模型卡](https://huggingface.co/google-bert/bert-base-uncased)。

| 参数 | 首轮预设 |
| --- | --- |
| 训练种子 | 42、43、44，三个独立初始化/训练过程 |
| 最大训练轮数 | 5；每个 epoch 在原生 validation 上评估并保存 |
| 学习率 / 优化器 | 2e-5 / AdamW |
| weight decay / warmup ratio | 0.01 / 0.1 |
| 有效 batch size | 16；显存不足时降低 microbatch 并用梯度累积维持 16 |
| max_length | 128；训练前检查 train/dev 的 WordPiece 长度与截断比例；若需调整，应在 test 评测前形成新计划版本 |
| 学习率调度 / 梯度裁剪 | linear / 1.0，显式保存参数 |
| 精度 | 首轮 FP32；BF16、INT8 后续作为独立变体 |
| 模型选择 | validation full60 Macro-F1 最大；同分保留较早 epoch |
| 其它 | 动态 padding；记录 determinism 设置、依赖锁、硬件、训练时长、峰值显存和产物哈希 |

首轮不做大规模超参搜索。三个种子都报告，不用 test 挑种子或挑 checkpoint。若后续增加学习率搜索，单独记录搜索预算、所有候选和验证选择过程。

已经为 Trainer 增加 Accuracy/full60 Macro-F1 的 `compute_metrics`，并启用每轮保存和 `load_best_model_at_end`；已用实际小型训练验证最终导出权重与最佳 checkpoint 相同。最佳模型选择 API 约束见 [Transformers 4.x Trainer 文档](https://huggingface.co/docs/transformers/v4.57.1/en/main_classes/trainer#transformers.TrainingArguments)；实际使用的 4.x 版本要锁定并验证，不能只依赖版本范围。

## 4. 最小完整实验矩阵

| 顺序 | 实验 | 输出及判断 |
| --- | --- | --- |
| A | 数据、模型 revision、环境与服务预检 | 冻结输入；小训练批次和单请求通过；健康检查、标签映射和产物校验正确 |

| C | 各 checkpoint 一次完整 test 低并发推理 | 3 × 2,974 条逐样本结果；Accuracy、full60 F1、supported59 F1、逐类指标、失败数 |
| D | 固定一个 checkpoint 的重复与 CPU/GPU 对照 | 按 dev 规则选择服务产物；分别重复完整质量评测三次，报告预测差异；复用已经完成的同配置首轮记录 |
| E | CPU/GPU 各自开放环负载测试 | p50/p95/p99、合法率、调度迟滞、goodput、correct goodput、资源占用 |
| F | 成本与错误分析 | 训练与搜索费用、部署费用、正确决策单位成本；三模型配对比较与混淆分析 |

训练种子差异与同模型重复推理差异分开报告。D 的服务产物按 dev full60 F1、dev Accuracy、较小 seed 依次选择；这是预先规定的部署选择，不能用最好的 test 分数决定。CPU/GPU 载入同一份权重，不另训两个模型；若输出有差异则报告并检查数值精度。

历史 Qwen 平均 Accuracy 为 45.9314%，Jev 为 86.1242%，这些仅为比较参照，不作为 BERT 必须达到的验收阈值。没有业务质量阈值时，只能报告质量和技术容量，不能宣布业务可用。

- 保留 sample_id、真值、预测、状态、训练 seed、推理轮次、模型版本和耗时。失败保留在质量分母；softmax 明确标为未校准。
- 主表给出三个 BERT 训练 seed 的各自结果与 mean ± sample SD；不将三个模型在同一测试集上的结果拼成 8,922 个独立样本。

- 每个训练 seed 分别计算配对 Accuracy 差值及 bootstrap 95% 区间，沿用历史 2,000 次、seed 42。抽样单位为 sample_id；同一模型重复推理不扩充样本量。区间不代表训练不确定性，训练 SD 另列。
- 若同一 test 内存在重复文本，再给出按规范化文本分组重采样的敏感性区间，防止把相同文本当成完全独立证据。

## 6. 性能实验必须注明部署条件

本机 RTX 5060 Laptop 可先做训练/服务可行性验证，但尚未实际跑过；用独立 Python 3.12 环境验证兼容依赖，避免直接改动当前 Python 3.13 全局环境。需要先做一个训练 step、一次推理和显存检查，才能判断 batch 配置是否可行。

历史 Qwen 在远程 RTX 5090 上测试。若要讨论同硬件的 CPU/GPU 部署差异，优先使用可恢复的原 Worker 环境，并让 Controller 独立运行；本机 5060 的结果可以单独报告，但不能与历史 5090 结果解释成纯模型速度差异。当前并未连接或租用远程 Worker。

当前 BERT 服务是单进程、单请求 batch=1、锁内串行推理，线程池排队计入端到端延迟。这适合作为透明的朴素基线，但不代表 BERT 优化部署的性能上限。后续动态 batching、ONNX/INT8 和多实例分别命名、分别重新测质量。

建议的负载流程：

1. 固定服务 artifact、精度、CPU 线程数（起点 4）、Controller、网络路径、timeout 30s、无应用层重试、warmup 50；明确并冻结 max_concurrency。
2. Pilot 从 1/2/4/8/16/32/64 RPS 逐档扫描，每档 120 秒 × 3 轮。全部通过则继续倍增；出现失败后定位瓶颈，不把客户端调度失败当成模型极限。最高档受资源/时间预算约束，不能从未测档位推算容量。
3. 在 pilot 前选择能覆盖计划并发的上限，并以 mock 服务校验 Controller 能跟上最高目标到达率。并发约束、连接池和资源若发生变化，要重新冻结配置及重测相关点。
4. 正式复测候选通过点及其相邻更高点，每档 300 秒 × 3 轮；按计划到达时间切 60 秒窗口，排空后将完成状态归回原窗口，不丢弃窗口边界的慢请求。
5. 沿用历史技术门槛：合法成功率 ≥99%、attempted E2E p95 ≤500ms、最大调度迟滞 ≤20ms；三轮及所有 60 秒窗口均需通过。goodput 分母包含发送窗口和排空时间。
6. 报告独立质量与 correct goodput。若没有档位通过，容量记为“未确认”，不是 0；通过点记为“最高已测通过点”。

PR 的历史分析执行源码未完整合入。本分支已补齐 BERT 的60秒窗口和配对统计实现，并提供独立测试；其版本单独记录，不冒充历史源码。

## 7. 成本和后续研究

按实际账单记录训练、全部尝试/搜索、预热、推理、空闲和常驻部署成本；推理侧同时报告每百万合法请求、每百万正确请求、每百万 SLO 内正确请求的费用。训练成本用明确生命周期请求量摊销，并报告低/中/高利用率场景。自有笔记本没有账单时先报告设备与耗时，不套用历史 5090 的每小时价格；不同币种保持原币，未经统一汇率和时点处理不做精确价格排名。

主线完成后优先做两类扩展：

- **标注数据量**：每类 1/5/10/20/50/全量的嵌套抽样、多个固定 seed，稀有类不足时披露实际数量，测试集固定。画质量与训练/标注成本曲线，更能解释监督学习的投入价值。
- **目录变化**：新增类、重训/更新耗时、新类质量、旧类退化与恢复时间。现有服务会对变化后的目录返回 409；必须实现显式模型更新后才能研究恢复能力。

历史 10/30/60 类实验是在固定 anchor 测试子集上增加候选干扰类，不能直接当成 BERT 改变分类头的实验。若做 BERT logits masking，必须单列为“已训练 60 类模型的候选过滤”；若分别重训 10/30/60 类模型，则单列为“训练任务规模”。这两种方法的训练信息与计算量不同。历史 anchor 资产尚未复原时，不声称实现了同子集配对。
